# 数据脱敏与合规基础规范

适用于来源材料、测试集、Run Artifacts、日志、截图、PR 和报告。P0 仅制定基础要求，不收集或提交真实卷宗。脱敏不自动消除授权、保密或其他法律义务。

## 授权与最小化

真实卷宗须在处理前核实合法来源、使用目的与范围，并取得必要的权利人、委托主体及相关主体授权，确认保密义务和适用的数据保护要求。记录授权依据、允许的使用/公开范围、期限及责任人；未明确授权的材料不得上传、进入测试集或发送给外部模型服务。公开裁判文书也不等于可任意再利用。

仅处理任务必需的信息；外部模型供应方的数据留存、训练使用和跨境传输条件须在真实数据使用前审核。授权和原始数据保存在独立受控位置，不进入公开仓库。

## 个人身份、金额与敏感信息

识别并移除或替换姓名、身份证件、地址、联系方式、银行账户、账号、签名、印章、案号及可关联定位个体的信息；处理商业秘密、医疗、财务、未成年人等敏感信息。主体与敏感金额必须脱敏，金额可采用经专业复核的区间化或合成替代；不得使法定金额阈值或事实关系失真而影响法律测试结论。

使用一致的占位标识保持关系，映射表单独受控保存，绝不随公开材料发布。检查附件元数据、批注、修订历史、图片、OCR、文件名、路径和日志中的间接标识，评估组合重识别风险。无法充分脱敏的材料不公开；由法律专家复核脱敏后事实是否仍支持测试目标。

## 合成数据优先

开发、校验器测试和 CI 优先使用完全合成的资料与占位链接，并显式标注用途。不得通过微改真实卷宗冒充合成数据；不得使用真实 API Key、个人身份信息或实际客户材料作为样本。合成测试通过只证明相应工程行为，不证明法律能力有效。

## 公开证据与保密数据隔离

Public 与 Holdout 及原始资料、映射表、授权记录分开管理。Holdout 题目、答案、可还原内容及原始完整运行快照不进入公开仓库或公开 CI；只发布经审核的安全汇总，遵循 [测评协议](EVAL_PROTOCOL.md) 的证据边界。

API Key、访问令牌、隐私数据和未授权材料禁止公开。密钥通过环境或安全的密钥管理机制提供，不写入样本、代码、命令记录和日志。`.gitignore` 仅降低误提交风险，不能代替人工审核及权限隔离。

公开前审核拟提交内容与 Git diff，检查密钥、身份信息、授权和脱敏结果；CI 不得打印私密输入。误泄漏按 [SECURITY.md](../SECURITY.md) 私密报告，立即轮换凭据并协调处置。后续任务需细化访问控制、保留期限、删除机制与复核流程；本文件不声称已通过合规审计。
