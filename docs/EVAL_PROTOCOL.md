# 控制变量测评基础协议

本文件定义 P0 基础约束，不实现测评引擎、不发布分数或声称方法已验证。以 [冻结路线图](../ROADMAP.md) 为准；复杂评分算法、统计阈值和专家一致性标准留待后续 P0/P2 任务细化并审核。

## 固定底座与单变量

Phase 1 测评 Skill 时，必须固定底座模型的供应方、精确版本/快照及运行环境；固定系统指令、数据源与工具权限、温度、top_p、最大输出 Token、随机种子（如支持）及重试/超时策略。记录不支持固定或受供应方变化影响的项目及限制，不把不可复现的设置描述为完全确定。

每次实验只放开一个被测变量：Skill、Data、Model 必须严格剥离。Phase 1 仅改变 Skill，设置使用同一模型、参数、输入与数据条件的基线对照组（例如不加载 Skill 的标准指令）。记录 Skill 内容版本/哈希、对照指令与差异；不得把数据或底座变化归因于 Skill。确需改变其他条件时分开实验并明确说明。

## Public / Holdout 隔离

公开自测集（Public）可用于开发与复现；盲测保留集（Holdout）须在公开仓库和 CI 之外的受控位置维护，由授权人员管理。不得在公开历史、日志、PR、报告、缓存、样本或运行快照泄露 Holdout 题目、答案或可还原片段。

记录测试集版本与访问权限，检测并记录污染/重叠风险；不得基于 Holdout 反复调优。访问、运行及发布流程由后续任务细化，经维护者批准后执行。当前 `tests/fixtures/` 仅为元数据校验的合成样本，不是法律测评 Public 或 Holdout 数据集。

## 法域与法规时效

正式条目必须显式标注法域，默认使用 `CN-Mainland`；按测试问题的事实发生时间、待判断时间、法域及法规生效/废止日期判断适用法律，不能仅凭抓取日期或模型知识截止日期推定有效性。

元数据 `regulatory_as_of` 是贡献者核对适用法律状态的基准日，不能代替个别法规的生效日期或对全部引用的复核。未知日期不得伪装为有效日期；事实或时间条件不足时标记待人工判断，不输出已确认适用的结论。

虚构法条或引用已废止旧法实行一票否决（0 分）。适用性及是否命中该红线须保留可追溯依据并由法律专家复核；历史场景或过渡条款的法律判断不能由格式校验器推断。

## Run Artifacts 与公开边界

每次评分须保留完整运行快照，以支持复现与追责，至少记录：运行标识/时间、代码与 Skill 版本/哈希、模型精确标识及参数、环境与依赖、测试集版本与用例标识、输入输出、引用来源及法律时效证据、Token/成本与计量口径、错误和重试、评分规则版本、评分证据及复核记录。

遵循路线图每次评分公开完整运行快照的可复现目标，同时必须遵守脱敏和 Holdout 隔离：Public 运行在授权和脱敏审核后公开完整可发布快照；Holdout 原始完整快照受控保存，公开版本仅包含经批准且无法还原保密内容的配置、汇总及复核记录，明确删减边界和复现限制。不得将删减版本宣称为可公开完整复现的 Holdout 证据。Holdout 完整公开复现与保密要求的最终协调方案是后续协议任务的待决事项，交维护者裁决，不改写冻结路线图。

## 专家复核与评分可追溯

法律专家应在可行时以盲测方式独立复核法域、法规时效、引用真实性及结论依据。每个评分须关联规则版本、证据位置、复核角色、意见、时间及修订记录；分歧须留痕并提交复核，不覆盖原始记录。

后续任务需明确评分细则、专家资质与人数、一致性统计及达标阈值。目前未验证任何相关系数阈值、排名或 Token 性价比结果。测评与路由结果仅供技术选型参考，不构成执业法律意见。
