# Gate1 权限分工与迁移兼容性报告

**本报告是 #14 的预审材料。Gate1 不批准托管、入库、专业意见或角色授权；全部法律来源与授权结论保持 not-verified。** 工程实现和完整测试由本轮独立工程证据记录确认，本报告不把设计要求描述为已上线能力。

## 可审查的改变

v2 用四块专家短表与五组问题入口减轻反复填写；底层仍保留 C01–C10 和 CR01–CR05／ZH01–ZH05／CN01–CN06，共46个检查项。范围仍为27／4／19文件，排除4／9／2320项（企业法务排除知识库2316项）。逐文件、逐检查项、来源/事实/时效/过渡、支持/反例、限制及待补正由结构化附件保存，不能靠分组把必需问题消失。

本人完成两步实质决定：

1. **专业决定**：具备相应能力且已获 main 角色授权的真人专家，核对材料后本人提交 Comment Review，表达通过范围、补正或拒绝以及理由/限制。
2. **独立入库决定**：已获 main 角色授权的 Human Maintainer，查看有效专业事件、权利证据、工程证据、用途和剩余阻塞后，以另一个本人事件作 admitted／declined／suspended 决定。不得由第一次事件自动派生，也不能将两个轴混进同一次事件。

可以由同一位已具备实际能力和已获授权的人承担两种角色，但必须分别作两个独立事件。一次性账号、角色、能力/资质核实与政策接受是启用前提，不是每轮新增第三次签署。v2 不要求另一个 rights_review 或 engineering_review 本人签署；相关事实和证据仍分别存在，最终维护者须明确评估。凡许可、范围或法律依据缺失，专业通过和CI绿灯都不解除阻塞。

## 权限与可验证边界

| 参与者/机制 | 可做 | 不能据此声称/执行 |
| --- | --- | --- |
| AI／工程准备者 | 原创问题整理、固定版本和逐文件映射、官方入口线索、格式预填、测试、生成待核附件、同步已核实本人事件 | 代填真实专业结论、造资质/许可材料、代签、自动批准、把摘要/字符串校验当法律正确性 |
| 真人法律专家 | 独立核实事实、具体法源和时效，判断支持性/例外，填写组/总体意见、限制和利益冲突，本人提交专业事件 | 以门户入口代替已核法条，以未授权材料可读性代替复制许可，以范围外知识库代表已审 |
| Human Maintainer | 一次性核实账号、能力/资质和角色；独立评估许可/用途/工程/专业证据并作入库决定；决定合并、暂停和复审 | 让分支自授角色，让同一事件兼作专业与入库决定，因任务数量目标降低证据门槛 |
| CI／可信同步器 | 校验结构、映射、冻结版本、本人事件与授权、撤销/编辑、期限、历史和并发，保守拒绝不能核验的输入 | 认证自然人真实身份/执业资格、断言法律有效性或获取授权，读取私有案卷正文 |

GitHub `User` 类型和 write 权限只能证明账号与可追溯操作，不证明自然人本人操纵或专业资质。AI明令不得使用真人令牌提交法律签署。身份、能力和共享账号风险需维护者在仓库外受控核实；公开只保留经本人允许的索引与摘要。

## v2 接收设计与上线前提

两条工作流分离：不可信提交只触发无权限 signal；后续 `workflow_run` 接收流程在可信 default branch 的 `github.workflow_sha` 检出固定工程代码，不执行PR分支工作流或脚本。接收器重新查询 main 中已接受的角色/v2政策、真实GitHub Review、User/write权限、已提交且未dismissed状态、精确 reviewed head／当前head，核验全历史事件是否编辑或撤销，使用并发比较更新保护避免旧head写入。

事件绑定固定 bundle（范围、源版本/manifest、模板版本/摘要、完整映射与证据），不能由提交者自己声称可信。工程验收必须证明未知字段、占位、漏项、范围变化、无效日期、权限撤销、事件编辑、错误head、历史替换、API失败和并发冲突都拒绝且不改旧记录。任何网络失败不得降级为信任本地签名文本。

Gate1合并前，PR内新工作流不会作为可信接收器运行。Gate2须由维护者单独接受实际本人账号/角色和 `credential_refs` 一次性不透明资质索引，初始应为空；不能为使测试通过而写入虚构真实索引。Gate1材料、合成测试和示例身份不得迁为真实授权。

策略草案中的 `max_regulatory_age_days=90` 只是工程有效期上限，供维护者判断和调整；它不是任何法规有效期间、专业意见有效期或90日内必然现行的法律结论。逐法适用版本、事实日期与过渡仍由专家判断。CI要求使用实际既有检查名称与GitHub Actions app ID `15368`；检查成功本身不构成法律或许可通过。

| 来源与manifest | 原commit、完整path/blob、eligible/排除决定保持；sidecar引用并绑定摘要 | 27／4／19不是托管许可；缩放或更新先新轮，不静默扩范围 |
| 模板与问题ID | C与专项ID逐一保留，G1–G5只是阅读分组 | 组通过不能掩盖未核check；模板版本变化有新摘要/新Review |
| v1四轴 | 对既有事件继续按v1规则处理 | v2新轮两步流程不能删除历史rights/engineering事件或给旧历史补造事件 |
| 权利与工程证据 | v2保留独立证据类别和状态，交维护者第二步核查 | 无真人第三次rights签署也不能把缺证改为verified；CI只标工程范围 |
| v2专业/入库事件 | 独立ledger存真实事件、head、绑定摘要及核验信息；完整重放 | 本人事件编辑/撤销或权限变化导致核验失败，保留失败原因并发起新轮，不覆盖历史 |
| 回退v1 | 停用v2接收/只读展示，保留sidecar与历史，继续原验证入口 | 不把v2事件自动写成v1合法四轴；无删除或重写历史的回退脚本 |

首次采用v2前应记录所有旧case与history/archive的摘要，验证本轮未改；之后同步只写本版本明确拥有的新记录。禁止混用 v1/v2 相同路径或让一个版本重解释另一个版本已签证据。旧Review ID若仅用来展示对应关系，不能因此继承旧批准或有效性；实际新版本决定绑定新的v2对象和来源基线。
